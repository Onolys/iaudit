## Review fix: automatic audit POST retries (2026-10-28)

Deviation from the original R5/D6 policy: automatic audit POST retries now apply only to HTTP 429. Review disproved the original assumption that 503 always precedes paid work: `eaudit/src/eaudit/app.py` maps `LLMUnavailable` to 503, and `eaudit/tests/pipeline/test_pl_degrade.py:64` exercises link-only unavailability after earlier stages. Repeating the POST can incur LLM cost again. The orchestrator chose the narrow frontend correction; HTTP 503 now returns immediately with the existing manual Retry action. Backend statuses/error taxonomy, detail-independent status decisions, idempotent eval GET retry, and all task completion statuses remain unchanged. The active SP01 PRD, task policy, branch locked decision, and dependent SP02/SP04 references have been corrected; historical artifacts are unchanged.
