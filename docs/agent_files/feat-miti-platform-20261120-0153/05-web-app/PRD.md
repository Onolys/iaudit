# PRD: SP05 web app — `web/` (app.onolys.com)

Repo/branch: Onolys/onolys (local `iaudit`) / `feat/miti-platform` · Depends on: SP04 `api/openapi.json` + `docs/contracts/public/*` (contract; builds against mocks until API is live), SP03 `engines/evaluation/schemas/report.schema.json` (the report contract; TS types generated from it), SP02 `rating.schema.json`/`report.yaml`; SP06 for Hosting site, DNS, Identity Platform config · Owns: `web/**` (incl. `web/firebase.json`, `web/src/api/` generated client, `web/src/mocks/`, `web/e2e/`), `docs/decisions/0021-web-app-hosting-and-sharing.md`

## TL;DR
A single-page React app that is a thin, typed consumer of the public `/v1` API (nothing else touches PHI). The Firebase web SDK is used for sign-in and for one read-only Firestore listener on the user's own PHI-free `session_status/{id}` document; every byte of session data (transcript, rating, report) goes through our API (or signed GCS URLs the API hands out). Served by Firebase Hosting on `app.onolys.com` with `/v1/**` rewritten to the Cloud Run `api` service (same origin). A mock mode (MSW + typed fixtures) lets the whole flow be built and tested before SP04 ships.

## Problem
Clinicians need a no-help path: sign up, upload a recording, fill in a rating card while it transcribes, confirm one machine guess (who is the clinician), wait a few minutes, read an evidence-linked report, and re-run. The report must be readable, non-judgmental ("Onolys disagrees, here's why"), and must never leak PHI into analytics, logs, browser storage, or the auth provider.
Verified: `frontend/` is React 19 + Vite 8 + TS + vitest with eaudit-specific contract/transport and span segmentation (`contract/spans.ts`, `app/ClaimText.tsx`, `tokens/`) [verified: `frontend/package.json`, `frontend/src/app/ClaimText.tsx`]; landing tokens (teal `#0b5f5a`, score good/fair/low chips with text labels, Inter) live in `onolys-landing/src/styles/tokens.css` [verified]. SP04 `GET /sessions/{id}/transcript` supplies turns (added in the reconcile pass).

## Goals / Non-Goals
**Goals:** all of scope below working end to end against the SP04 stub API in `SERVICE_MODE=combined`; usable on a phone; WCAG 2.1 AA basics; 100 MB upload with progress and recovery; zero third-party scripts.
**Non-goals (v1):** PDF export, teams, billing, email, trends, transcript editing, non-English UI/report, account-deletion endpoint, audio playback synced to transcript, offline, i18n, SSE, file upload or paste-to-parse of ratings.

## Requirements
**R1 Routes** (react-router, SPA):
| Route | Auth | Content |
|---|---|---|
| `/signup` `/login` `/forgot-password` | public | email+password forms, "Continue with Google"; links between them; `?next=` honoured |
| `/verify-email` | signed-in, unverified | "Check your inbox", Resend (cooldown 60 s), "I've verified" (reload + force-refresh token), auto-check on tab focus |
| `/` | verified | Dashboard (R5) |
| `/sessions/new` | verified | Upload form (R3) |
| `/sessions/:id` | verified | Status timeline + gate steps + errors + delete |
| `/sessions/:id/reports/:version` | verified | Report (R4); `version` = integer |
| `/settings` | verified | API key, usage, sign out |
Guards: unauthenticated → `/login?next=`; unverified → `/verify-email`; API 401 after one forced token refresh → sign out → `/login`. Unknown id → API 404 → friendly "not found" (never reveals other users).

**R2 Auth.** `firebase/auth` modular only (no analytics/other SDKs). Persistence: SDK default (IndexedDB); app stores nothing else. Every request calls `user.getIdToken()` (SDK refreshes ~5 min before expiry); a 401 triggers exactly one `getIdToken(true)` retry. Email verification: `sendEmailVerification` with continue URL `/verify-email`; after verification the cached token still lacks `email_verified`, so force-refresh before calling the API (API requires `email_verified=true`). Google sign-in: popup, redirect fallback on mobile/popup-blocked; `authDomain = app.onolys.com` (Hosting serves `/__/auth/*` on the custom domain). Forgot password: always shows the same confirmation (no account enumeration). Open sign-up, no allowlist. Error messages mapped to plain text (wrong password, weak password: minimum 8 characters and no other rules, email in use → offer login). No two-factor/MFA. Sign-out clears the query cache.

**R3 Create session** (`/sessions/new`): one short form, then a three-step submit; transcription starts as soon as the upload completes and the user fills the rating card on the session page meanwhile:
1. Fields: audio (drag-drop/choose; mp3 wav m4a webm ogg; ≤100 MB), language dropdown (`Auto-detect` default + list from a static BCP-47 allowlist), Advanced (collapsed `<details>` disclosure): `n_runs` (1–5, default 1) and `preset` select, both rendered from `GET /v1/presets` (hidden if only one preset is listed); title optional. Change goal and "coded from–to" live in the rating card (R4), not here. [RESOLVED: API accepts `n_runs` and allowlisted `preset`; web shows them under Advanced (reconcile pass)]
2. Client pre-checks (advisory; server is authoritative): size, extension/MIME, duration via `HTMLAudioElement` metadata (>25 min blocks with message; <10 min shows the warning that globals are unreliable).
3. Submit: `POST /sessions` (`Idempotency-Key` = UUID per form instance) → `POST …/audio` → navigate to `/sessions/:id` at once, where an app-level uploader keeps going: `PUT` file to signed URL with **XMLHttpRequest** (fetch has no upload progress), exact signed `Content-Type`, progress bar with MB/%, cancel button, `beforeunload` guard while uploading → `POST …/audio/complete` (returns 202; transcription starts immediately). Upload failure/expiry (15 min URL): request a fresh URL and retry the whole object up to 2 times automatically, then show "Retry upload" on the session page (session exists in `created`). Chunked resumable upload is out of v1 [DEFERRED]. The rating-card draft is held in React state only (never localStorage).

**R4 Session page + report.**
*Status:* subscribe to the Firestore document `session_status/{id}` with `onSnapshot` (firebase/firestore; owner-only read by security rules; fields `state, step, progress, error_code, latest_report_version, updated_at`, no PHI); no polling and no ETag. Unsubscribe on leave; on listener error or permission-denied fall back to one `GET /sessions/{id}` and show the error card. Timeline (`aria-live="polite"` status text) steps: Upload · Check audio · Transcribe · Confirm speaker · Your rating · Rate session · Report, with copy "Usually under 5 minutes — you can close this tab and come back; your report will be here." Elapsed time shown, no fake percentages beyond `progress`. The run starts automatically when transcript + speaker confirm + rating card (or "no rating") are all in; state `awaiting_rating` shows "Waiting for your rating".
*Speaker gate* (`awaiting_speaker_confirm`): per speaker a card with the 3 sample lines (plain text) and "This is the clinician"; submit `POST …/speakers/confirm`. No editing.
*Rating card* (shown on the session page from the moment the session exists, so it can be filled while the file uploads and transcribes; can be submitted any time before or after transcription finishes and edited until a run starts; later edits apply to the next run). Fields: change goal (required), coded from–to (mm:ss pair → `coded_span{from_s,to_s}`, optional; helper text "only if you rated part of the recording"); for each global (Cultivating Change Talk, Softening Sustain Talk, Partnership, Empathy): score 1–5 or "not rated", reason textarea (≤1,000 chars) and an optional timestamped example (`mm:ss` + text ≤1,000 chars) [RESOLVED: 1,000 chars (Tejit r6)]; for each of the 10 behaviour codes: count (int or blank) + optional note textarea (≤1,000 chars). Plus ONE separate free-text box "Additional notes / evaluation reasoning" (≤3,000 chars) with helper text that it is **not** parsed into the card: Onolys checks what you write there against the transcript. **Soft caps:** a live character counter on every free-text field that warns past the limit and does not block typing; the API is the hard limit (rejects >1,000 per item and >3,000 notes with `422 rating_invalid`; the form then shows the per-field message). Buttons: "Submit rating" (`PUT /sessions/{id}/rating`; partial allowed) and "No rating — just rate my session" (submits only change goal and optional span). There is no rating upload, paste-to-parse or confirm step. Labels, 1–5 anchors and the 10 codes come from the static `protocol/miti-items.ts` (parity-tested against `rating.schema.json`). [RESOLVED: rating card only (Tejit 2026-11-20 r6)]
*Speaker gate* is above; the card and speaker gate are independent and can happen in either order.
*Failure:* error card with plain message per code table (`unsupported_audio`, `audio_too_long`, `audio_too_large`, `audio_unreadable`, `rating_invalid`, `upstream_unavailable`, `daily_cap_reached`, `invalid_state`, `rate_limited`, generic), the `request_id` as "reference", and: failure at `validate`/`transcribe` → "Upload a different file" (new session, params prefilled); later failures → **Run again** (`POST …/runs`).
*Delete:* confirm dialog stating audio, transcript, rating, all report versions are removed permanently → `DELETE` → dashboard.
*Report* (`/sessions/:id/reports/:version`; version→report id via `GET …/reports`): two-pane on desktop (report left, transcript right, sticky), single column with a "Transcript" bottom sheet/tab on mobile. Sections in the order of the report's `layout[]` (`{section, title, items?}`, SP03 R7; sections the UI does not know are skipped): (1) header from `header{change_goal, protocol{label}, models, n_runs, rating_coverage}` + `created_at`: change goal, MITI 4.2.1, models, date, version switcher (v1…vN with date + models; default latest), **Run again**; (2) `scorecard[]`: per item "You | Onolys | difference chip" from `clinician.value`, `onolys{value,mean,min,max,values[]}` and `diff{signed,abs,direction,status,within_one?}` (chip text like "Onolys +1" from `signed`; `status` `agree|differs|flagged|not_rated|no_onolys_value` picks the tone; colour never alone; no rating → Onolys column only, "–" elsewhere); (3) "Onolys disagrees, here's why" blocks only for `differs|flagged` items, from `globals[]`/`behaviours[]` `explanation{headline, body[], onolys_lines[], clinician_support_lines[]}` (lines carry `{turn_id,start,end,quote}`; each a button → scrolls/highlights in transcript; Onolys's lines vs lines supporting the clinician are labelled; the headline text comes from the report, not hard-coded); (4) globals (`globals[]`: Onolys `score` + `reason` + `evidence[]` lines, your score + reason); (5) behaviour counts table (`behaviours[]`: `clinician_count`, `onolys_count{mean,min,max,values[]}`) with instance chips from `instances[]` (`{id,turn_id,start,end,quote,rationale}`; `instances_total` above the number shown → "+N more") (click → jump to and pulse highlight in transcript; keyboard operable; note "these are Onolys's instances; a tally-only self-rating can't be matched line by line"); (6) `summaries[]` (`clinician`/`onolys` value + label vs `reference{fair,good}`, `note`) vs reference levels with copy "reference levels, not pass marks" and fair/good ticks; (7) `reasons_audit` (`status` `ran|partial|skipped|failed`; per item `claims[]` with eaudit `verdict` shown as supported / partly supported / not supported (`contradicted`) / not enough evidence (`insufficient_evidence`); `out_of_scope` claims are not shown; evidence lines by `role`; `skipped` (no-rating run) hides the section; `partial` adds a note); (8) `tips[]` (3–5 by `rank`; `item_id` tag, `observation`, `quote{turn_id,start,end,text}`, `alternative`, `why_it_matters`); (9) `method{statement, limits[], citation}` note (shown verbatim; `not_official_miti_coding` is always true). N>1: values shown as mean with range ("2.7, runs 2–3"), instances from the representative run (labelled). Unknown future sections are skipped; `schema_version` (stored by SP04 as `report_schema_version`) major mismatch shows "This report was made by a newer version — refresh". `warnings[{code,item_id?}]` (e.g. `fewer_tips`, `reason_withheld_tone`, `short_session`) render as quiet notices.
*Transcript:* turns from `GET /sessions/{id}/transcript` with speaker label (`role`: Clinician/Client after confirm), timestamps (`start_ms`), highlight segments computed by a generic segmenter. Offsets from paudit/eaudit are **code points**, JS strings are UTF-16: convert via a code-point→UTF-16 index map (tested with emoji/accents). Rendered only as React text nodes (no `dangerouslySetInnerHTML`, no markdown/HTML parsing of any model or user text).

**R7 Typed client + mock mode.** `openapi-typescript` generates `web/src/api/schema.d.ts` from `api/openapi.json` (copied/committed; `npm run gen:api`; CI fails if stale vs `api/openapi.json`); the report body is an opaque object in OpenAPI, so `json-schema-to-typescript` generates `web/src/api/report.d.ts` from `engines/evaluation/schemas/report.schema.json` in the same script and staleness check, and mock fixtures are validated against that schema in tests; `openapi-fetch` wrapper adds auth, base URL (`/v1`), `Idempotency-Key`, error-body parsing (`public-error-response`) and the 401 retry. **R8 Privacy/security/a11y.** No analytics, GA, trackers, error-reporting SDKs, or remote fonts (Inter self-hosted, copied from landing); only `firebase/auth`, `firebase/firestore` (the one status-doc listener) and first-party code; Firestore is initialised with a memory cache (no IndexedDB persistence). `localStorage`/`sessionStorage`/IndexedDB hold no app data (Firebase's own auth entry only); no PHI in URLs (ids only), `console` output, document titles, or error messages. Hosting headers: CSP (`default-src 'self'; script-src 'self'; connect-src 'self' https://identitytoolkit.googleapis.com https://securetoken.googleapis.com https://firestore.googleapis.com https://storage.googleapis.com; frame-src https://accounts.google.com https://*.firebaseapp.com; img-src 'self' data:; style-src 'self'; frame-ancestors 'none'`), `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`, `Cache-Control: no-cache` on HTML, immutable on hashed assets, `private, no-cache` expected on `/v1` responses (API to set). The exact CSP hosts for the Firestore listener and the Identity Platform popup are confirmed on staging. A11y: semantic landmarks, labelled inputs, error summary with focus, focus moved to `h1` on route change, `aria-live` on status, keyboard-operable chips/gates, ≥4.5:1 contrast (landing tokens already AA), `prefers-reduced-motion`, 44 px targets, `eslint-plugin-jsx-a11y` + `vitest-axe` on every page. Mobile: single column ≥320 px, tables collapse to cards.

**R9 Tests.** Vitest + Testing Library + MSW: unit (code-point segmenter, difference chips, error mapping, token retry, upload progress with mocked XHR, status listener handling (snapshot → timeline, permission-denied fallback), rating form parity with the copied `rating.schema.json`, soft-cap counters), page tests per route, and **flow tests** (sign-up→verify→upload→speaker + rating card filled during transcription→report; no-rating run; failure→run again; cap reached; delete session; API key once-only). ## Architecture
```
Browser (app.onolys.com, Firebase Hosting: static dist/)
  ├─ firebase/auth ───────────────► Identity Platform (sign-in only, no PHI)
  ├─ firebase/firestore onSnapshot ► Firestore `session_status/{id}` (owner-read rules, no PHI)
  ├─ /v1/**  (Hosting rewrite) ───► Cloud Run `api`  (Bearer ID token)
  └─ PUT signed URL (XHR) ────────► GCS audio bucket (CORS allow app origin; SP06)
```
```
web/
  index.html  vite.config.ts  firebase.json  package.json  .env.example
  src/{main.tsx, App.tsx, routes/, auth/, api/{schema.d.ts,client.ts,errors.ts,upload.ts,hooks/},
       features/{dashboard,session,report,settings}/, lib/{spans.ts,codepoints.ts,format.ts},
       protocol/miti-items.ts, styles/{tokens.css,app.css}, mocks/{handlers.ts,fixtures/}}
  e2e/  (Playwright)
```
Report/transcript data flow: `GET /reports/{rid}` (typed JSON; instances carry `turn_id`, `start`, `end` code-point offsets) + `GET /sessions/{id}/transcript` → `buildSegments(turn, instances)` → selected instance id in URL hash (`#i=…`, ids only) drives scroll + highlight. Item labels, reference levels and ordering come from the report JSON (`scorecard[].label`, `summaries[].reference`, `layout[]`), so the UI stays protocol-agnostic; only the rating-card form uses the static `protocol/miti-items.ts` (labels, 1–5 anchors) with a parity test.

## Acceptance Criteria
1. `npm run typecheck && lint && test && build` pass in `web/` with no network; `gen:api` produces no diff against committed `api/openapi.json`.
2. In mock mode, full flow works: sign-up → verify → create session (100 MB fixture shows progress, cancel works) → rating card filled while transcription runs, speaker confirm (3 lines each) → run starts automatically → `report_ready` via the status listener → report v1; Run again creates v2; switcher shows both; delete removes session.
3. Report shows scorecard with difference chips (text + tone), disagreement blocks with evidence, clickable instances that scroll/highlight in transcript, "reference levels, not pass marks", tips, method note; N=3 fixture shows mean + range; no-rating fixture shows "–" in dashboard tiles and Onolys-only scorecard.
4. Code-point offsets highlight correctly on a transcript containing emoji and combining accents; no `dangerouslySetInnerHTML` in `web/src` (lint rule).
5. Token handling: expired token → one forced refresh then retry; second 401 signs out; unverified user cannot reach `/`.
6. Rating card: soft-cap counters warn past 1,000/3,000 without blocking typing; an over-limit submit shows the API's per-field `rating_invalid`; card submits before, during and after transcription; no upload or paste-to-parse control exists; the notes box is separate and labelled as not parsed.
6a. Failure states: each mapped error code renders its message + reference id; `validate`/`transcribe` failure offers new upload, later failure offers Run again; cap reached disables Run again with reset time.
7. Settings: API key secret visible once, absent after dismiss/reload, never in storage or logs (test inspects `localStorage`, `sessionStorage`, console spy).
8. No requests to hosts outside the CSP list in Playwright network log (incl. `firestore.googleapis.com`); no polling of `GET /sessions/{id}` while a session runs (status arrives by listener); no analytics code; axe finds no serious violations on any route at 375 px and 1280 px.
9. Against SP04 `SERVICE_MODE=combined` with fake auth, the Playwright full-session flow passes (run once SP04 lands).
10. `web/firebase.json` contains the `/v1/**` rewrite before the SPA fallback, CSP/headers above, and a staging target; deploys to staging verified by SP06.
