Method: line-by-line read of App/main, routes, auth/*, api/*, features/*, lib, hosting csp + firebase.json. `npm run typecheck` and `npm run lint` clean. ## UX questions for the owner (product choices)

1. Header by state: signed out = Log in / Sign up / Sample report only? Signed in = add Sign out + account email in header (today sign out only exists on Settings and VerifyEmail)? Unverified = only "Verify email"?
2. Should signed-out visitors see Sample report at all (it is public today and is the only nav that works signed out)?
3. Signup/reset: add confirm-password and a show-password toggle? Keep "8 chars, no other rules"?
4. After password reset, send user to login (today) or auto-sign-in?
5. Preserve the deep link (`next`) through verify-email via the email link (needs continue URL change) - worth it?
6. Email enumeration policy: Signup says "email already exists" but Forgot password hides existence. Keep this split?
7. Google sign-in when the email already has a password account: link accounts, or show "use your password"?
8. Mid-interview refresh: allow rejoin (partial recording) or block with "interview ended"?
9. Abandoned uploads (session created, file never uploaded): auto-delete after N hours, allow resume from the session page, or leave visible?
10. Lost live updates: auto-poll silently, or keep the manual "Refresh" notice?
11. Dashboard: auto-refresh in-progress session chips, or only on revisit?
12. Forgot password with a malformed email: show "enter a valid email" (small enumeration risk: none) or always the generic confirmation?
