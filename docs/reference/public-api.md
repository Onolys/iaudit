# Public API (`/v1`)

**Audience:** users and API-key clients.

The contract is [`api/openapi.json`](../../api/openapi.json) (generated by `python -m onolys_api.openapi`, checked in CI). The running service serves it at `/v1/openapi.json` and a Redoc page, with a curl quickstart, at `/v1/docs`. Both are public (no auth); the page loads no script or font from another host. Machine-readable body schemas: [`docs/contracts/public/`](../contracts/public/). Why it looks like this: [ADR 0020](../decisions/0020-public-api-contract.md).

## Conventions

- JSON over HTTPS, all paths under `/v1`, every resource scoped to the calling user. Another user's id is `404`, never `403`.
- Auth: `Authorization: Bearer <Identity Platform ID token>` or `X-API-Key: onolys_<id>_<secret>` (`POST /v1/api-key`; one active key; the secret is shown once).
- Mutations return at once. Calls that start work return `202`; the session `status` then moves `created` → `uploading` → `validating` → `transcribing` → `awaiting_input` → `running` → `report_ready` (or `failed`). Poll `GET /sessions/{id}`.
- Path ids are `{id}` (session), `{run_id}` and `{version}` (report version, an integer: the public report address). `{report_id}` is reserved for the stored report id and is not used in a path today.
- `POST /sessions` takes an `Idempotency-Key` header (1-128 chars). The same key and body within 24 h replays the first response (header `Idempotent-Replayed: true`); the same key with a different body is `409 conflict`. No other endpoint stores keys.
- Every response carries `X-Request-ID` (an inbound one of up to 64 safe characters is honoured).
- CORS: `app.onolys.com` (and staging, localhost in dev); headers `Authorization`, `X-API-Key`, `Idempotency-Key`, `Content-Type`.
- Not in the API: presets listing, dashboard aggregates, a top-level reports collection.

## Operations

| Operation | `operationId` | What it does |
|---|---|---|
| `GET /healthz` | `getHealthz` | Liveness (no auth) |
| `GET/POST/DELETE /api-key` | `getApiKey`, `createApiKey`, `deleteApiKey` | Key metadata, create (revokes the current), revoke |
| `POST /sessions` | `createSession` | Create (`language`, `n_runs` 1-5, `preset`, `title`, `interview_id`) |
| `GET /sessions` | `listSessions` | Newest first, in-flight and failed included; `limit`, `cursor` |
| `GET /sessions/{id}` | `getSession` | Status snapshot with flags |
| `DELETE /sessions/{id}` | `deleteSession` | Hard delete of everything; `204` once storage is empty |
| `POST /sessions/{id}/audio` | `requestAudioUpload` | Signed PUT URL (up to 300 MB) and the `required_headers` to send |
| `POST /sessions/{id}/audio/complete` | `completeAudioUpload` | Upload finished; validation starts |
| `GET /sessions/{id}/audio` | `getAudio` | Short-lived signed read URL |
| `GET /sessions/{id}/transcript` | `getTranscript` | Transcript (roles once the clinician is confirmed) |
| `GET /sessions/{id}/speakers` | `getSpeakers` | Speakers with sample lines |
| `POST /sessions/{id}/speakers/confirm` | `confirmSpeakers` | Pick the clinician speaker |
| `PUT /sessions/{id}/rating` | `putRating` | `final=false` autosaves a draft; `final=true` writes a revision |
| `GET /sessions/{id}/rating` | `getRating` | Latest final revision and a newer draft |
| `POST /sessions/{id}/runs` | `startRun` | Re-run on the same transcript (counts against the evaluation caps) |
| `GET /sessions/{id}/runs` · `GET /runs/{run_id}` | `listRuns`, `getRun` | Run status and `run_info` |
| `GET /sessions/{id}/reports` | `listReports` | Report versions |
| `GET /sessions/{id}/reports/{version}` | `getReport` | One report |
| `GET /scenarios` | `listScenarios` | Practice-client scenarios (public fields only) plus the selectable voices |
| `POST /interviews` | `createInterview` | Start an AI practice interview (`scenario_id`, optional `voice`) |
| `GET /interviews/{id}` | `getInterview` | Interview state and elapsed duration |
| `POST /interviews/{id}/end` | `endInterview` | End (or `discard`) an interview; idempotent |
| `GET /usage` | `getUsage` | Per kind (`eval`, `interview`) and period (`day`, `month`): `used`, `cap`, `resets_at` |

`operationId`s are stable: client generators key on them.

## Errors

Every non-2xx body is `ErrorResponse` ([schema](../contracts/public/public-error-response.schema.json)):

```json
{"schema_version": "0.0.1", "request_id": "…", "status": 422,
 "message": "…", "details": [{"code": "rating_invalid", "message": "globals/cct/reason: too_long",
                              "field": "globals/cct/reason", "issue": "too_long"}]}
```

`details[].code` is a closed enum (a superset of the eaudit one). Messages are fixed text and paths, never user content. `field` and `issue` are set on `rating_invalid` only: `field` is the `/`-joined card path (`$` = the whole card), `issue` is one of `invalid_type`, `too_long`, `out_of_range`, `required`, `unknown_key`, `invalid`, `order`, `too_large` (the evaluation engine's `validate_rating` issues, plus the API size cap `too_large`); at most 20 issues are listed.

| Status | Codes |
|---|---|
| 401 | `unauthenticated` |
| 403 | `forbidden` |
| 404 | `not_found` |
| 409 | `invalid_state` (wrong session state, an inconsistent run request, or `interview_id` of an interview that has not ended), `conflict` (idempotency key reused with another body, or `interview_id` already linked to a session) |
| 422 | `invalid_parameters`, `unsupported_audio`, `audio_too_large`, `rating_invalid` |
| 429 | `daily_cap_reached` (evaluation day cap or concurrent-run limit), `monthly_cap_reached` (evaluation month cap), `interview_cap_reached` (AI interview day or month cap), `rate_limited` |
| 503 | `upstream_unavailable` (retry shortly) |
| 500 | `internal_error` |

The three cap codes carry `period` (`day` or `month`) in `details[]` (optional field): `daily_cap_reached` is `day`, `monthly_cap_reached` is `month`, `interview_cap_reached` is `day` or `month`. When both periods are exhausted the month code is returned.

`GET /usage` returns:

```json
{"eval": {"day": {"used": 3, "cap": 10, "resets_at": "2026-11-22T00:00:00Z"},
          "month": {"used": 41, "cap": 100, "resets_at": "2026-12-01T00:00:00Z"}},
 "interview": {"day": {"used": 0, "cap": 5, "resets_at": "…"}, "month": {"used": 2, "cap": 30, "resets_at": "…"}}}
```

`cap` is the effective cap (per-user overrides included); `used` may exceed it after a cap is lowered. `resets_at` is the next UTC midnight (day) or the 1st of the next UTC month (month). The first evaluation run of an AI-interview-linked session is free (does not count) but still takes a concurrent-run slot.

Failures found by the worker (not an HTTP error) appear as `error.code` on the session: `unsupported_audio`, `audio_too_long`, `interview_too_long` (interview audio longer than `AI_MAX_SECONDS` + `AI_TOLERANCE_SECONDS`, 630 s by default) (recording over 20 minutes, the Chirp 3 batch limit; set by `max_audio_s` on the STT provider in `stt_providers.yaml`), `audio_unreadable`, `no_speech`, `speakers_not_separated`, `transcription_failed`, `upstream_unavailable`, `deadline_exceeded`.

## AI practice interviews

The clinician role-plays against an AI client; the recording then goes through the normal upload and evaluation path. Why Gemini and a relay: [ADR 0024](../decisions/0024-ai-practice-interview-gemini-live-relay.md).

`GET /scenarios` returns `{"scenarios": [{"id", "title", "difficulty", "summary", "language", "voice"}], "voices": [...]}`. `voices` is every voice a practice interview may use; each scenario's `voice` is its default (used when `POST /interviews` omits `voice`; the web picker always sends one). Only these public fields are returned; the persona, hidden information and response rules never leave the server.

`POST /interviews {"scenario_id", "voice"?}` returns `201` with `interview_id`, `voice_url` (the relay base URL), `scenario`, `voice` (the chosen or default voice), `state` and `limits {max_s, warn_s}` (default 600 s and 480 s). It takes one `interview` usage unit first: `429 interview_cap_reached` (with `period`) when the day or month cap is spent, `422 invalid_parameters` for an unknown scenario or voice. An earlier unfinished interview of the same user is abandoned lazily at this point.

`GET /interviews/{id}` returns the state and `duration_s`. `POST /interviews/{id}/end {"discard"?: bool}` ends the interview (or abandons it when `discard` is true) and is idempotent. Another user's interview is `404`.

States: `created` → `live` → `ended` | `abandoned` → `uploaded` (set once the linked session's audio upload completes). An interview that ends or is abandoned under 30 s (`AI_ABANDON_COUNT_SECONDS`) refunds its usage unit, once. A sweeper abandons interviews stuck in `created` or `live` after `AI_MAX_SECONDS` + `AI_RECONNECT_SECONDS` + 60 s.

To evaluate an interview, `POST /sessions` with `interview_id`: the interview must be the caller's (404 otherwise), `ended` (409 `invalid_state` otherwise) and not already linked (409 `conflict`). The session takes `language` and a default `title` from the scenario, and its rating draft is prefilled with the scenario's change goal. The first evaluation run of such a session is free (see `GET /usage`). `GET /sessions` and `GET /sessions/{id}` carry `interview_id` (`null` for plain uploads).

Validation of interview audio: longer than `AI_MAX_SECONDS` + `AI_TOLERANCE_SECONDS` (630 s) fails with `interview_too_long`; shorter than `AI_MIN_SECONDS` (300 s) warns `short_interview` (instead of `short_recording`).

### Voice relay (WebSocket)

`wss://<voice-host>/v1/voice/{interview_id}` on the separate `onolys-voice-{env}` Cloud Run service; the host is `voice_url` from `POST /interviews`. It is not part of `openapi.json`.

- The browser's `Origin` must be an allowed CORS origin, else the connection is refused.
- First client frame (within 10 s): `{"type": "auth", "id_token": "<Identity Platform ID token>"}`. Close code `4401` for a missing or bad token, `4403` for another user's interview, `4404` for an unknown interview, `4409` when the interview is not `created` or `live`.
- Client to server: binary frames of PCM16 mono 16 kHz audio; text `{"type": "end"}` to finish.
- Server to client: binary frames of PCM16 mono 24 kHz audio, and text messages `ready` (`resumed`, `elapsed_s`, `max_s`, `warn_s`), `ai_speaking` (`on`), `interrupted` (drop queued AI audio), `warn` (`at_s`, 480 s), `time_up` (600 s; the relay ends the interview), `error` (`code`).
- A dropped client can reconnect to the same URL within 60 s (`AI_RECONNECT_SECONDS`): the interview resumes with elapsed time carried over (`ready.resumed` is true). After 60 s it cannot.

## Engine errors

What a failed run or transcription turns into (`api/src/onolys_api/adapters/error_map.py`, `to_public(exc, attempt, stage) -> (code, retryable)`). Every failure is mapped to one existing public code above; the message is fixed text per code, never the exception message. Each mapped failure writes one worker log line with `status=failed`, `error_code` and `exc_class` (the runbook query finds it by `request_id`). `retry` is whether the worker makes another attempt (attempt limit 2).

| Code | Raised by (engines) | Retry | What the user does |
|---|---|---|---|
| `invalid_parameters` | `InputError`: pack input checks (too long, no change goal, too few clinician or client turns), unknown preset | no | Fix the input (e.g. change who the clinician is) and run again |
| `upstream_unavailable` | LLM unavailable, timeout, rate limited or bad output after the engine's own retries; a transient STT provider error on attempt 1 | yes | Run again |
| `deadline_exceeded` | Internal run deadline passed, `TimeoutError`, eaudit `DeadlineExceeded` | yes | Run again |
| `transcription_failed` | STT permanent error; a second transient STT error; no result within the poll limit | no | Upload a different file |
| `no_speech` | Transcript with 0 turns or under 50 words | no | Upload a different file |
| `speakers_not_separated` | Fewer than 2 usable speakers | no | Upload a different file |
| `rate_limited` | Adapter error that already carries this code | yes | Try again shortly |
| `internal_error` | `PackError`; any other exception, including engine `run_failed` errors with no LLM cause; an adapter code outside this table | no | Run again; the owner is alerted |

An eaudit or tips failure inside the evaluation is not an error: the report is made with warning `reasons_audit_failed`, `reasons_audit_partial` or `tips_failed` and the session ends `report_ready`.

## Quickstart

The same script is the intro of `/v1/docs`; a test runs it against a combined-mode server. See the [`/v1/docs`](https://app.onolys.com/v1/docs) page or the `info.description` of `openapi.json`.

## Regenerating

```
uv run --package onolys-api python -m onolys_api.openapi     # api/openapi.json
uv run --package onolys-api python -m onolys_api.contracts   # docs/contracts/public/*.schema.json
```

CI job `api` regenerates both and fails on any diff.
